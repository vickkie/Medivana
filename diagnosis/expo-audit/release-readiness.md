## Store-readiness gaps

- **Privacy/data safety**: medical app collecting health data, payments, images, and chat. No `expo` privacy manifest info reviewed; Play Data Safety form must declare: AsyncStorage user data, Firebase RTDB chat content, uploaded images, payment reference (Paystack), expo push tokens.
- **Account deletion**: `Profile.jsx:105-119` implements delete → API call + cache clear + logout (surface satisfies the Play/Apple deletion requirement); `components/Profile/DeleteAccount.jsx` is an empty file — remove it or wire it; confirm backend actually deletes server-side (backend audit flagged unauthenticated routes — verify `DELETE /api/user/delete-account/:id` is authed).
- **Payments**: Paystack hosted-page flow is the right PCI posture **but** `Checkout` still transmits `cardNumber` to the own API (SEC-03) — must be removed before any real card processing.
- **Crash reporting**: none. A medical app shipping to stores without Sentry/Crashlytics/EAS insights is flying blind. `react-native-error-boundary` shows a fallback UI only.
- **OTA**: decide — either install `expo-updates` + correct `updates.url` (`https://u.expo.dev/{projectId}`) and a channel strategy, or remove the config + `UpdateCheck` APK-download prompt entirely (a Play-distributed app prompting users to sideload APKs is a policy problem, not just a bug).
- **Deep links**: no `scheme` — verify none is needed for payment callbacks (Paystack flow uses in-app WebView interception, so OK).
- **README/docs**: fine for humans; no `CHANGELOG`, no release notes process.

## Environment / config drift

- `BACKEND_PORT` in `.env` is unverifiable in the audit (gitignored). **Required check**: it must be `https://` in every build profile — the sibling repos' dev setups use `http://192.168.x.x`/`localhost`, and a leaked http endpoint ships JWTs + passwords + medical data in cleartext.
- `.env` carries `ONESIGNAL_REST_API_KEY` (unused) — remove before it accidentally ships (SEC-04).
- `react-native-dotenv` has no whitelist — treat all `@env` vars as public permanently.

## Regression risk notes

- App has **zero automated tests** — any release change is verified by hand only. The remediation plan in `tracker.md` is sequenced to land independently-verifiable chunks precisely because of this.
- `versionCode 10` + version `2.3.0` in sync — keep bump discipline per release.

## Verdict

**Not store-ready** in current state: fix P0 crash + P1 security items, then re-baseline. The skeleton (EAS config, signing flow, permissions, Paystack verification) is workable — the gaps are hygiene and the security items in `security.md`, not architecture.
