# Security & privacy audit — Medivana client app

Scope: shipped client bundle only. Backend vulnerabilities are out of scope (see `/home/quinzel/projects/medivana-audit/` for the server-side audit, which found unauthenticated data routes and an unlocked Firebase RTDB). Client-side `.env` values were inspected by **name only** (via `expo-doctor` output); no secret values were read or reproduced.

## Additional notes (verified)

- **No `http://` URLs in source** — all traffic uses `BACKEND_PORT`. **Action required:** confirm `.env` `BACKEND_PORT` is `https://`. If it's `http://IP:port`, this becomes **Critical** (cleartext JWTs, passwords at `LoginPage.jsx:66`, medical data). The gitignored `.env` couldn't be read under audit rules; historical eas.json used an https Vercel URL (Promokings).
- No deep-link `scheme` configured; Android permissions minimal (`POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, `VIBRATE` — `app.json:32-36`).
- `jwt-decode` client-side role checks (`AuthContext.js:102-125`, `position` claim) — fine for UI; **not authorization** — backend must enforce (backend audit says it doesn't — cross-ref MED-SEC).
- `react-native-get-random-values` polyfill loaded for `uuid` in chat screens — fine.
- `scripts/unpack-google-services.js` decodes `GOOGLE_SERVICES_JSON` env → writes `google-services.json` at `eas-build-pre-install` — reasonable CI pattern; file is gitignored (verified never committed).
- `components/Profile/DeleteAccount.jsx` is **empty (0 lines)** but account deletion IS implemented inline in `Profile.jsx:105-119` (API call + cache clear + logout + nav reset) — satisfies Play Store deletion requirement at surface level; backend must actually delete.
