## Error-handling observations (verified)

- Most axios calls are try/catch'd — baseline OK — but error UX is inconsistent (toasts vs silent vs raw `Alert`).
- `Checkout.jsx:325` sets `setErrorMessage(error)` with the **Error object**, not `error.message` → renders `[object Object]`/crashes the text node.
- `Checkout.jsx:127` `catch (_) {}` inside the 4-s payment poller — intentional, fine, but add a counter so it can't poll forever if backend is down.
- `react-native-error-boundary` mounted once at root (`screens_options/ErrorBoundary.jsx`) — good coverage, **no reporting attached** (no Sentry/Crashlytics dep).
- Loading/empty states inconsistent: `useFetch` exposes `isLoading`/`error` but consumers render ad hoc; checkout uses lottie, lists use plain text.

## Navigation notes

- `key={i}` index keys on `Stack.Screen` (App.js:107) — fragile but harmless for a static list.
- `navigationRef` created (`Helpers/NavigationService.jsx`) but never passed to `NavigationContainer` — dead service; deep notification taps use `useNavigation` inside the tree instead.
- Tab "Orders" renders `Appointments`; `OrderDetails` → `AppointmentDetails` — naming drift to fix when touching the barrel.
